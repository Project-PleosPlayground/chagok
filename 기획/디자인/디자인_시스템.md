# 디자인 시스템

앱 화면의 공통 규칙을 모은 문서다. 색·글자 이름, 컴포넌트, 패턴, 문구를 다룬다. 화면을 고치거나 새로 그릴 때 이 문서부터 본다. Claude로 디자인을 고칠 때도 이 문서를 먼저 읽힌다.

화면의 모습은 이 문서와 영역 사양(`기획/화면/`)이 정본이다. 색·글자 값은 이 문서 4절 팔레트 표와 5절 글자 표가 정본이고, 문구는 UI 텍스트.csv가 정본이다. `CSV/`의 색·폰트 파일은 빌드가 읽지 않는다. 피그마 시안은 참고 자료다. 팀이 정할 것(문구, 누르는 동작, 미션·아이템 규칙)은 `[제안]`으로 표시하고, 결정은 이슈에서 한다.

## 이 문서를 쓰는 법

### 무엇이 어디에 있나

| 무엇 | 정본 |
|---|---|
| 화면 모습 | 이 문서와 영역 사양. 피그마 시안은 참고 |
| 색 값 | 이 문서 [4절 팔레트](#팔레트) |
| 글자 모양 | 이 문서 [5절 글자](#글자) |
| 화면에 고정된 글 | [UI 텍스트.csv](CSV/UI%20텍스트.csv) |
| 컴포넌트 그림 | `Image/Component/`, `Image/Icon/` |
| 화면별 위치 규칙 | `기획/화면/영역사양_<화면>.html` |
| 스테이지(캐릭터·아이템 영역) 크기와 자리 | [스펙_스테이지 "스테이지"](../스펙_스테이지.md#스테이지) |
| 미션·아이템 동작 | [07 미션](../07_미션.md), [08 아이템](../08_아이템.md) |
| 공통 레이아웃 규칙, 컴포넌트 구성과 상태, 패턴 | 이 문서 |
| 앱 코드의 값과 컴포넌트 | 값은 `android/app/src/main/java/ai/safetypoc/app/ui/theme/`, 컴포넌트는 그 옆 `ui/component/`. 이름은 이 문서 이름을 camelCase로(`primary_blue` → `primaryBlue`, `tab_button` → `TabButton`). 색·글자 값이 4·5절 표와 같은지는 단위 테스트 `DesignSystemSyncTest`가 확인한다. 주행 중인지는 `LocalDriving`으로 읽고, 주행 중에는 움직임을 쓰지 않는다(2절). 정차 중에 쓸 애니메이션은 `[미정]` |
| 한눈에 보기(색, 글자, 모서리·그림자, 컴포넌트 그림) | [디자인_시스템_보기.html](디자인_시스템_보기.html). 이 문서와 그림으로 만든 생성 파일 |

화면 사양은 이 문서의 컴포넌트 이름으로 요소를 부른다. 컴포넌트를 바꾸면 그것을 쓰는 화면 사양도 함께 바뀐다.

### 표시

| 표시 | 뜻 |
|---|---|
| `≈` | 캡처에서 잰 지금 값. 디자인을 바꾸면 따라 바뀐다 |
| `[제안]` | 팀이 정할 제안(문구, 누르는 동작, 미션·아이템 규칙). 이슈에서 정하면 표시를 뗀다 |
| `[미정]` | 아직 값이 없다 |
| `[확인필요]` | 외부 문서·기기에서 확인할 것 |
| `가안` | 다른 기획 문서(06 등)에서 쓰는 표시. 임시로 정한 값이라 바꿀 수 있다 |

### 고치는 순서

| 바꿀 것 | 고칠 곳 |
|---|---|
| 색 하나, 글자 크기 하나 | 4절 팔레트 표나 5절 글자 표의 그 줄, 그리고 앱 테마(`AppPalette.kt`, `AppTypography.kt`)의 같은 이름. 고친 뒤 `node 기획/화면/공통/build.js`로 공통 CSS, 영역 사양, 보기 페이지를 다시 만든다. 앱 값이 표와 다르면 `:app:testDebugUnitTest`가 실패한다 |
| 4절 팔레트 표, 5절 글자 표의 열 | 열을 더하거나 순서를 바꿔도 된다. 머리글 `이름`·`값`(4절), `역할`·`크기`·`굵기`(5절)는 build.js와 `DesignSystemSyncTest`가 찾으므로, 바꾸면 둘도 고친다 |
| 투명도, 모서리, 그림자, 컴포넌트 크기 | 이 문서의 그 표, 그리고 앱 테마의 같은 이름(`android/app/src/main/java/ai/safetypoc/app/ui/theme/`). 두 곳을 손으로 맞춘다 |
| 영역 사양의 모양(범례, 표, 캡처 토글) | `기획/화면/공통/`의 spec.css, spec.js. 고친 뒤 같은 명령으로 다시 만든다 |
| 컴포넌트의 구성·상태·크기 | 이 문서의 그 컴포넌트. 그 컴포넌트를 쓰는 화면 사양을 확인한다 |
| 화면 하나의 배치 | 그 화면의 영역 사양 |
| UI 배치를 바꿔 스테이지 자리·크기도 바꿔야 함 | 스테이지 값은 스펙_스테이지를 따른다(`가안`). 바꿔야 하면 스펙_스테이지와 #30에서 정한다. 정하면 홈·주행·상점 사양의 스테이지 박스도 같이 고친다 |
| 새 컴포넌트 | 이 문서 6절에 먼저 추가하고 화면에 쓴다 |

Claude에게 시킬 때 예:
- "디자인 시스템 7절 confirm_popup의 버튼 규칙대로 상점 구매 팝업 문구를 고쳐 줘"
- "mission_card 도전 중 상태의 바탕색을 바꾸고, 쓰는 화면 사양을 같이 고쳐 줘"
- "새 화면 settingView를 이 문서 컴포넌트로만 조립한 영역 사양으로 만들어 줘"

### 용어

| 용어 | 뜻 |
|---|---|
| dp | 화면 밀도와 상관없는 길이 단위. 피그마 1 px = 1 dp |
| 화면 여백 a | 창 가장자리에서 UI까지 비워 두는 거리(48 dp) |
| `↑a`, `↑←a`, `↓→a` | 위 / 위·왼쪽 / 아래·오른쪽 여백 a에 붙인다. 화살표가 붙는 쪽이다 |
| Hug contents | 내용 크기에 맞춰 늘고 준다(피그마 Auto layout 용어) |
| 컨테이너 | 다른 요소를 담는 상자 |
| 빈 곳 | 화면에서 UI가 없는 사각 영역. 스테이지 크기를 정할 때 쓴다(스펙_스테이지) |
| 스테이지 | 캐릭터, 펫, 소품을 놓는 영역(스펙_스테이지) |
| L0~L3 | 그리는 층. L0 창, L1 스테이지, L2 UI, L3 팝업·알림 |

## 1. 원칙 `[미정]`

디자인 의도를 3~5줄로 적는다. 이 절이 비어 있는 동안에는 2절을 지키고, 나머지는 3~8절을 따른다.

- 분위기: `[미정]`
- 주행 중 한눈에 볼 것: `[미정]`
- 화면마다 가장 먼저 보일 것(정보 위계): `[미정]`

## 2. 꼭 지킬 것

바꾸면 안 되는 기준이다. 근거는 Pleos 주행 안전 가이드(driver-distraction-guideline), 팀 기획 문서, 차량 앱 품질 기준이다. 다른 앱 종류의 기준을 참고로 가져온 것은 근거 칸에 "참고"로 적는다. 그 밖의 값(3~8절)은 디자인을 바꾸면 함께 바꿔도 된다.

| 기준 | 내용 | 근거 |
|---|---|---|
| 주행 중 움직임 | 애니메이션, 스크롤, 움직이는 그림을 쓰지 않는다. 숫자·막대는 바로 바꿔 보인다 | Pleos 주행 안전 가이드 "시선 분산 최소화": 동영상·애니메이션·움직이는 이미지를 최소화하거나 제한한다. 이 앱은 그보다 엄격하게 쓰지 않는다(팀 결정). 스크롤 금지도 팀 결정 |
| 주행 중 조작 | 메뉴를 비활성으로 둔다. 키보드 입력과 설정 변경은 정차 중에만 | [02 주행·정차 분기](../02_화면목록.md#주행정차-분기-확정) |
| 주행 중 미션 표시 | 주행 중에는 판정하지 않는다. 진행도만 바뀐다. 이번 주행의 성공·실패는 주행이 끝난 뒤에 보인다 | [07 판정 시점](../07_미션.md#판정-시점) |
| 메뉴 구조 | 드롭다운과 여러 단계 메뉴를 많이 쓰지 않는다. 자주 쓰는 기능은 첫 화면이나 위쪽에 둔다 | Pleos 주행 안전 가이드 "정보 구조·인터랙션" |
| 터치 대상, 글자 | 크게, 대비 높게, 글은 짧게 | Pleos 주행 안전 가이드 "터치 조작 최적화" |
| 누르는 영역 | 64 × 64 dp 이상. 보이는 모양은 작아도 누르는 영역은 64로 둔다 | [Car app quality](https://developer.android.com/docs/quality-guidelines/car-app-quality) UX-1 (정차용 앱 종류의 기준을 참고로 가져옴) |
| 누르는 영역 사이 | 서로 24 dp 이상, 화면 가장자리에서 24 dp 이상 | Car app quality UX-2 (참고) |
| 글자 크기 | 24 sp 이상 | Car app quality UX-3 (참고) |
| Pleos 자체 기준 | `[확인필요]` Pleos 주행 안전 가이드는 버튼 크기·간격을 Pleos Connect UI Design Guide에 맡기고 수치를 적지 않았다. 그 가이드의 값이 위와 다른지 | |
| 창 모양 | 2칸 창과 1칸 창을 모두 지원한다 | [스펙_스테이지 "기준 화면"](../스펙_스테이지.md#기준-화면) |

## 3. 기초

모든 화면에 같은 값을 쓴다. 값은 지금 시안 기준이다.

| 항목 | 값 |
|---|---|
| 기준 기종 | Connect-S-17 (17인치, 160 dpi). 기종별 창 크기는 [스펙_스테이지 "기준 화면"](../스펙_스테이지.md#기준-화면) |
| 창 | 2칸 창 1700 × 1184, 1칸 창 840 × 1184 |
| 화면 여백 a | 48 dp. 모든 UI는 a 안쪽 |
| 크기·간격 | 8의 배수 |
| 박스 | 레이아웃 박스. 그림자·빛 번짐은 박스 밖이고 여백 계산에서 뺀다 |
| 그리는 순서 | L0 창 → L1 스테이지 → L2 UI → L3 팝업·알림 |
| 스테이지와 UI | 스테이지를 먼저 놓고 UI를 그 위에 깐다. UI가 스테이지를 가려도 된다 |
| 스테이지 자리 | 크기·피봇·자리는 스펙_스테이지. 홈·주행은 창 정중앙, 상점은 오른쪽 영역 가운데 |
| 컨테이너 | 고정 높이, 위부터 채움, 넘치면 숨김. 스크롤하는 목록은 그 화면 사양에 적는다 |

### 화면 뼈대

탭 화면(홈, 주행, 미션, 통계)은 왼쪽에 tab_bar를 둔다. 아이템 상점, 프로필, 온보딩은 메뉴 없이 창 전체를 쓴다.

| 자리 | 요소 | 쓰는 화면 | 위치 |
|---|---|---|---|
| 왼쪽 위 | tab_bar | 탭 화면 모두 | ↑←a. 탭을 바꿔도 같은 자리 |
| 오른쪽 위 | coin_bar | 홈, 주행, 주행 결과, 아이템 상점 | ↑→a |
| 가운데 위 | exp_bar | 홈, 주행 | ↑a, 가로 중앙 |
| 가운데 | 스테이지 또는 탭 내용 | | |
| 가운데 아래 | drive_start_button / drive_end_button | 홈 / 주행 | ↓a, 가로 중앙 |

## 5. 글자와 모양

### 글자

값은 아래 표가 정본이다. 글꼴은 Roboto. 크기 3단계 × 굵기 2개만 쓴다. 이름은 `크기_굵기`다. 모두 2절 기준(24 sp 이상)을 지킨다.

| 역할 | 크기 (sp) | 굵기 | 쓰는 곳 예 |
|---|---|---|---|
| `large_bold` | 40 | Bold | 화면 안내, 팝업 제목 |
| `large_regular` | 40 | Regular | 프로필 이름 |
| `medium_bold` | 32 | Bold | 섹션 제목, 상점 제목, 아이템 이름, 메뉴, 주행 버튼 |
| `medium_regular` | 32 | Regular | 지금 쓰는 곳 없음 |
| `small_bold` | 24 | Bold | 카드 제목, 숫자, 버튼 글자, 차 이름 |
| `small_regular` | 24 | Regular | 설명, 팝업 본문, 칩, 도움말 |

컴포넌트 그림의 그림자를 세 단계로 묶는다. 값은 피그마 표기(아래로 y, 흐림, 불투명도)다. SVG 파일의 `stdDeviation`은 흐림의 반이다.

## 6. 컴포넌트

크기는 2칸 창 기준 dp다. 컴포넌트 그림에서 잰 값을 8의 배수로 맞췄다. `≈`는 캡처나 그림에서 잰 값 그대로다. 누르는 요소는 2절 기준(누르는 영역 64 이상)을 따른다.

컴포넌트 이름은 그림 파일 이름을 따른다(상태 꼬리 `_default`, `_selected` 등을 뗀 것). "그림" 칸은 `Image/` 안의 전달용 SVG다. 앱은 컴포넌트 SVG를 그대로 쓰지 않고 표의 정보(구성, 상태, 색·글자, 크기, 모양)로 다시 그린다. 그림은 모양을 확인하는 데 쓴다. 그대로 쓰는 것은 아래 셋이다.

- 아이콘(`Image/Icon/`, 이름이 `_icon`으로 끝남): SVG를 VectorDrawable로 바꿔 쓴다([06 UI 아이콘](../06_아트_리소스.md#ui-아이콘)). 색은 앱에서 칠할 수 있다.
- 캐릭터·아이템 그림: [06](../06_아트_리소스.md) 규격대로 그대로 쓴다.
- platform(car_picker의 발판): SVG의 흐림·번짐 효과를 VectorDrawable이 그리지 못해, SVG를 투명 배경 PNG(2배)로 바꿔 쓴다. 디자인 원본 PNG가 오면 파일만 바꾼다.

그림과 이 문서가 다르면 이 문서를 따른다. 다른 곳은 각 표의 "그림과 다른 점"에 적는다.

### 확인 팝업 (`confirm_popup`)

되돌리기 어려운 일 앞에서 묻는다. 할 수 없는 이유를 알릴 때(포인트 부족)도 같은 모양을 쓴다.

- 구성: 제목(`large_bold`) + 본문(`small_regular`, `ink` 84%, 없어도 됨) + 버튼 2개. 폭 800, 높이 = 내용. 모서리 `radius_xl`, 그림자 `shadow_soft`.
- 창 정중앙에 뜬다. 뒤는 scrim(`ink` 40%)으로 창 전체를 덮는다. 팝업 밖을 누르면 닫힌다 `[제안]`.
- 안쪽 배치(여백, 간격, 버튼 크기)는 [영역사양_팝업](../화면/영역사양_팝업.html)에 있다.
- 버튼은 왼쪽 `button_dark` = 하려는 일, 오른쪽 `button_light` = 닫기.
- 버튼 글자는 "예/아니요" 대신 하는 일로 쓴다 `[제안]`.

### 누르기

- 미션 탭
  - 제공 카드: 누르면 도전 팝업.
  - 도전 슬롯의 카드(도전 중, 성공, 실패): 눌러도 반응이 없다. 길게 누르면 도전 중은 도전 취소 팝업, 성공·실패는 슬롯 비우기 팝업.
  - 완료 미션 카드와 mission_blank: 눌러도 길게 눌러도 아무 일이 없다.
  - 길게 누르는 동작은 화면에 보이지 않으므로 도전 중인 미션 안내 말풍선(`mission_info_challenge`)에 적는다.
- 상점: 아이템 슬롯을 누르는 동작은 08을 따른다.

## 8. 문구

- 해요체로 쓴다. 묻는 말은 "~할까요?"로 쓴다 `[제안]`.
- 같은 것은 같은 이름으로 부른다. 도전 슬롯의 미션은 어디서나 "도전 중인 미션"이다(`mission_topic`).
- 버튼 글자는 하는 일로 쓴다 `[제안]`.
- 숫자: 포인트는 천 단위 쉼표(33,456). 진행은 "3/10".
- 남은 시간: 24시간 미만은 `HH:MM:SS`, 24시간 이상은 "N일 남음" `[제안]`.
- 날짜: `YYYY.MM.DD` `[제안]`.
- 고정 문구는 [UI 텍스트.csv](CSV/UI%20텍스트.csv)에 키로 넣는다. 키 규칙은 [데이터 컬럼 사전](../데이터_컬럼_사전.md#ui-텍스트).

## 확인 필요

| 항목 | 내용 |
|---|---|
| 정차 중 화면에서 주행 시작 | 미션·상점·프로필·온보딩 화면을 보고 있을 때 주행이 시작되면 주행 화면으로 바꿀지, 입력 중인 글은 어떻게 할지 |
| 1칸 창의 팝업·알림 폭 | confirm_popup과 알림의 폭(최대) 800은 2칸 창 기준이다. 1칸 창(840)에서는 양옆이 20씩 남아 화면 여백 a(48)와 누르는 영역 간격(24)보다 좁다. 1칸 창 값을 따로 정할지 |
| mission_info 시간 | 두 줄 글을 1초에 읽기 어렵다. 다음 누르기까지 둘지 |
| 버튼 두 개의 보조 버튼 | 프로필 저장·취소는 외곽선, 팝업은 밝은 회색. 하나로 맞출지 |
| `ink`와 `ink` | 하나로 합칠지 |
| profileView_edit_delete 캡처 | profileView_3 캡처와 같은 그림이다. 삭제 화면 캡처 확인 |
