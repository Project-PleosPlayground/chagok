## 2. 정본과 갱신 규칙

버전의 정본은 이 문서가 아니라 빌드 파일이다. 이 문서는 사람이 한눈에 보도록 옮겨 적은 것이다.

- 라이브러리·플러그인 버전: `android/gradle/libs.versions.toml`
- 모듈별 의존성과 SDK 수준: 각 모듈의 `build.gradle.kts`
- Gradle 버전: `android/gradle/wrapper/gradle-wrapper.properties`

버전이나 의존성을 바꾸는 PR은 이 문서도 같이 고친다(CONTRIBUTING 2절 "스펙 문서는 코드와 같은 PR").

## 3. 모듈 구성

앱은 모듈 셋으로 나뉜다. 의존 방향은 `:app → :core → :engine`이고, 거꾸로는 의존하지 않는다.

| 모듈 | 종류 | 맡는 것 | 의존 규칙 |
|---|---|---|---|
| `:engine` | 순수 Kotlin (JVM) | 안전점수 엔진: 신호 처리, 이벤트 검출, 점수, 음성 발화 결정 | Android·Pleos SDK 의존 없음 (`스펙_안전점수.md` 6절) |
| `:core` | 순수 Kotlin (JVM) | 화면 뒤 로직: 저장(인터페이스와 구현), 미션, 성장, 코인·아이템, 세션 종료 처리, 리포트 집계, 원격 콘텐츠 판단 | Android 의존 없음. `:app`은 저장 매체(`DocumentStore`)의 파일 구현만 넣는다 (#10) |
| `:app` | Android 앱 | 화면, Pleos SDK·AAOS 신호 입력, 음성 재생, 엔진 호스트 | 유일하게 Android·Pleos SDK를 쓴다 |

`:engine`과 `:core`가 순수 JVM이라 Android 에뮬레이터 없이 단위 테스트로 로직 전부를 검증할 수 있다.

패키지 최상위 이름

| 모듈 | 패키지 |
|---|---|
| `:engine` | `engine` |
| `:core` | `core` |
| `:app` | `ai.safetypoc.app` |

- 순수 Kotlin 모듈은 패키지 최상위 이름을 모듈 이름과 같게 한다.
- `:app`은 Android 관례에 따라 도메인 모양 이름을 쓴다. 이 이름이 리소스 클래스(`R`) 위치와 앱 식별자(`applicationId`)로 쓰인다.
- 앱 이름(#21)이 정해지면 세 모듈을 `ai.<앱 이름>.engine`, `.core`, `.app`으로 함께 바꾼다 `[제안]`.

### `:core` 패키지

경로는 `android/core/src/main/kotlin/core/` 기준이다. 테스트도 같은 패키지에 둔다.

| 패키지 | 넣는 것 |
|---|---|
| `content` | 콘텐츠 묶음(미션·아이템·캐릭터 목록, 점수 구간, 엔진 수치), 읽기·검증, 원격 교체와 재시도 (#31, #33) |
| `mission` | 미션 정의와 받은 미션, 발급·판정(판정은 주행 끝), 주행 중 진행도, 미션 저장소, 미션 종류 enum |
| `character` | 캐릭터 종류(번호·이름·그림 폴더)와 고르기, 프로필, 프로필 상태(고른 캐릭터, 코인, 가진 아이템, 스테이지 배치), 캐릭터별 성장(별칭, 경험치·단계), 코인 쓰기(구매)와 스테이지 배치 저장, 프로필 저장소 |
| `item` | 아이템과 아이템 번호, 아이템 종류 enum(펫, 소품, 배경), 스테이지 배치 규칙(놓기·빼기·옮기기·저장 정리, 08 "스테이지 배치"). 다른 패키지를 쓰지 않는다 |
| `session` | 세션 기록, 차량 상태, 세션 저장소, 종료 애니메이션 enum |
| `report` | 리포트 집계 |
| `flow` | 여러 기능을 묶어 부르는 처리: 세션 종료 처리(저장 → 미션 판정 → 경험치·코인 → 요약) |
| `store` | 저장 매체 인터페이스(`DocumentStore`), 저장 문서 JSON(`StoreCodec`), 프로필·세션·미션 저장소의 문서 저장 구현 (#10) |
| (루트) | 여러 패키지가 같이 쓰는 것: 날짜 경계(`Time`), 넘침 없는 덧셈 |

- 종류 enum(미션 조건, 아이템 종류, 종료 애니메이션 등)은 각 기능 패키지에 둔다. 판정·표시 코드와 같이 바뀌므로 원격 콘텐츠로 바꾸지 않는다.
- 구매와 스테이지 배치 저장(`Wallet`)은 프로필 상태를 바꾸므로 `character`에 둔다. `character`는 `item`을 쓰고, `item`은 `character`를 쓰지 않는다.
- 아이템과 캐릭터 종류는 정수 번호로 가리킨다(`ItemId`, `CharacterId`, #48). 번호는 종류마다 붙고 목록 순서와 무관하다. 한 번 붙이면 바꾸지 않고, 지운 번호는 다시 쓰지 않는다. 사용자 저장 데이터가 이 번호를 가리키기 때문이다.
- 고른 캐릭터·코인·아이템은 프로필 상태(`ProfileState`)에, 별칭·경험치·단계는 캐릭터 성장(`CharacterProgress`)에 둔다(#48).
- 내장 기본 목록(`BundledContent`, `DefaultMissions`, `DefaultItems`)은 `content`에 둔다. 서버에서 아무것도 받지 않은 첫 실행에도 이 내장 묶음을 쓴다.
- 기능 패키지는 콘텐츠를 직접 읽지 않고 필요한 목록만 받는다. 미션 엔진은 미션 목록, `Wallet`은 아이템 목록. `:app`이 `ContentState.active`에서 꺼내 넘긴다.

패키지 사이 의존 방향 (`A → B`: A가 B를 쓴다). 거꾸로 쓰지 않는다.

```
flow      → content, mission, character, session
content   → mission, item, character, session
mission   → session
character → item
report    → session
```

경로는 `android/app/src/main/java/ai/safetypoc/app/` 기준이다. 패키지 이름은 앱 이름(#21)이 정해지면 바꾼다.

| 패키지 | 넣는 것 |
|---|---|
| `ui/home` | 정차 홈 (`02_화면목록.md`) |
| `ui/driving` | 주행 중 화면 |
| `ui/report` | 세션 리포트 (주행 종료 뒤) |
| `ui/history` | 주행 기록 목록 (#16) |
| `ui/mission` | 미션 탭, 미션 오버레이(도전 슬롯과 진행도) |
| `ui/decorate` | 꾸미기: 상점(아이템 슬롯, 개별 아이템 페이지의 구매·적용), 스테이지 배치 편집과 저장 |
| `ui/settings` | 설정 |
| `ui/nav` | 화면 이동. top-level destination이 바뀔 때 받아 둔 원격 콘텐츠를 적용한다 (#31) |
| `ui/theme` | Compose 테마: 색, 글꼴, 크기 |
| `ui/stage` | 스테이지 그리기(좌표, 그리는 순서, 아이템 끌어 옮기기) |
| `ui/art` | 캐릭터·아이템 그림 읽기와 캐시 (#42) |
| `ui/transform` | 변신 영상 재생 |
| `data/store` | 저장 매체(`DocumentStore`)의 기기 파일 구현 (#10) |
| `drive` | 주행·정차 판별 (`CarUxRestrictionsManager`) |
| `content` | 원격 콘텐츠 다운로드와 받은 파일 보관 (#31) |
| `source` | 차량 신호 입력: Pleos Vehicle SDK, AAOS |

- 화면 패키지 이름은 `02_화면목록.md`의 화면 후보를 따른다 `[제안]`. 화면이 바뀌면 이 표도 고친다.
- 엔진 호스트(`EngineHost`), 앱 설정(`AppConfig`), 진입점은 패키지 루트에 둔다.
- 아직 파일이 없는 패키지는 `.gitkeep`으로 남긴다.

### `:app` 리소스 위치

경로는 `android/app/src/main/` 기준이다.

| 폴더 | 넣는 것 | 파일 이름 |
|---|---|---|
| `res/drawable/` | UI 아이콘. SVG를 VectorDrawable로 바꿔 넣는다 (`06_아트_리소스.md` "UI 아이콘") | `ic_<이름>.xml` `[제안]` |
| `res/values/` | 화면 문구 (`strings.xml`) | 문자열 키는 영문 소문자와 `_` |
| `res/raw/` | 효과음. 쓸지와 형식은 `[미정]` (#1) | `sfx_<이름>.ogg` `[제안]` |
| `assets/character/` | 캐릭터 정지 그림·주행 자세·프로필 그림, 변신 영상. 차종마다 폴더 하나 | `06_아트_리소스.md` "캐릭터" |
| `assets/item/` (빌드가 만든다) | 펫, 소품, 배경 그림. 저장소의 `src/main/assets/`에는 두지 않는다 | `<이미지 값>.png` (`06_아트_리소스.md` "폴더 구조") |

- 캐릭터·아이템 그림은 `assets/`에 둔다 (#42). 어떤 그림을 띄울지를 데이터(차종, 단계, 아이템)가 정하므로 경로 문자열로 찾는다.
- 캐릭터 그림 경로와 없을 때 대신 쓰는 순서는 `:app`의 `ui/art/CharacterArt.kt`(`CharacterArt`), 읽기·캐시는 같은 파일의 `CharacterArtStore`(앱 최대 메모리의 1/16).
- 아이템 그림의 원본은 `기획/디자인/Image/Item/` 한 곳이다. 빌드할 때 Gradle 작업 `syncItemArt`가 그 아래 PNG만 `app/build/generated/` 아래로 복사하고, 그 폴더를 assets 소스로 더한다. APK 안 경로는 `assets/item/<Item/ 아래 상대 경로>`다. SVG와 `Item/` 밖의 그림은 들어가지 않는다.
- 이미지 값 → assets 경로 변환과 규칙은 `core.item.ItemImage`, 읽기·캐시는 `:app`의 `ui/art/ItemArt.kt`(`ItemArt` 컴포저블, `ItemArtStore`).
- 원격 콘텐츠(#31)는 JSON만 받는다. 그림은 APK에 든 것만 쓴다. 새 그림이 필요한 아이템은 앱 업데이트로 낸다.

- 화면 문구는 코드에 직접 쓰지 않고 `strings.xml`에 둔다. 앱 표시 이름(`app_name`)은 #21에서 정한다.
- 색, 글꼴, 크기 같은 테마 값은 `res/values/`가 아니라 Compose 테마(Kotlin)에 둔다 `[제안]`.
- 빈 폴더는 `.gitkeep`으로 남긴다. `res/` 아래 폴더에는 리소스 파일만 둔다. 설명 파일(`README.md` 등)을 넣으면 빌드가 실패한다.

## 8. 서버와 외부 서비스

| 서비스 | 쓰임 | 비고 |
|---|---|---|
| Supabase Storage | 원격 콘텐츠 manifest·데이터·리소스 파일 배포 | 정적 파일만. 실행 코드(Edge Function)와 DB는 쓰지 않는다 (#31). 앱에는 공개 읽기 주소만 둔다 |
| AI 중계 서버 (Vercel, TypeScript) | 주행 끝 1회 호출: 주행 리포트 문장 생성. 앱 → 서버 → Claude API | Claude 키는 서버 환경변수에만 둔다. 앱은 앱 토큰 헤더로 호출. 통신 실패 시 앱 내장 규칙 문장 (#13, `server/README.md`). 개인 미션은 앱 안 규칙으로 고르므로 AI 호출 없음. **보내는 항목**: 요일·시간대·출퇴근길 추정, 거리(km 정수)·시간, 점수, 이벤트 종류·주행 몇 분째·단계·속도, 7일 집계, 습관, 개인 미션 이름·결과, 캐릭터 이름·단계 (`core/ai/AiPayload.kt`). 위치·도로명·날짜·정확한 시각·VIN·사람 이름은 보내지 않는다. **동의**: 프로필마다 사용자가 켜야만 보낸다(기본 꺼짐), 끄면 바로 멈춘다. 안내 문구는 앱 안 `ai_consent_notice`, 설정 화면 토글은 #101 |
| Pleos Maven | Pleos SDK 받기 | |

로그인 서버와 사용자 계정은 없다. 차 한 대(앱 설치 하나)에 프로필을 최대 3개 두고, 데이터는 기기 안에 저장한다. 밖으로 나가는 것은 동의한 프로필의 AI 리포트 입력(위 표)뿐이고, 중계 서버는 저장하지 않는다.

### 기기 안 데이터 저장 (#10)

| 항목 | 값 |
|---|---|
| 저장하는 것 | 프로필, 프로필 상태(고른 캐릭터·코인·아이템·배치), 캐릭터 성장, 주행 기록(세션), 받은 미션 |
| 방식 | 레코드 하나를 JSON 문서 하나로 저장한다. 앱 전용 폴더 `files/store/<모음>/<키>.json` |
| 모음 | `profiles`, `profile_states`, `character_progress`, `sessions`, `missions` |
| 문서 모양 | `{"schema": 1, "updatedMs": <마지막으로 쓴 시각>, "data": {...}}`. 저장 모양을 바꾸면 `schema`를 올리고 이전 버전을 옮기는 코드를 더한다. 앱보다 새 `schema` 문서는 읽지 않는다 |
| 읽기·쓰기 | 앱을 켤 때 전부 읽어 메모리에 둔다. 쓰기는 저장 스레드 하나에서 순서대로 한다. 임시 파일에 쓰고 디스크에 내려 쓴(fsync) 뒤 이름 바꾸기로 교체한다 |
| 읽지 못한 문서 | 건너뛰고 로그에 남긴다. 원본은 `<모음>_skipped` 모음에 옮겨 두어, 같은 키를 새로 써도 남는다 |
| 미션 순서 | 같은 시각에 제공된 미션은 넣은 순서로 보인다. 문서에 넣은 순서(`seq`)를 같이 저장한다 |
| 백업 | 클라우드 백업에 넣지 않는다(`allowBackup=false`). 주행 위치가 들어 있다 |
| AI 리포트 동의, 설정 | SharedPreferences (`AiConsent`, `AppSettings`) |

- Room·DataStore를 쓰지 않는다. 레코드가 많지 않고(프로필 3개, 주행 기록 수백 건) 세션처럼 목록이 든 레코드가 많아 문서 하나로 두는 편이 단순하다. 새 라이브러리 없이 `:core`에서 단위 테스트한다.
- 서버 저장을 더할 때는 저장 매체 `DocumentStore`를 하나 더 구현한다. 같은 (모음, 키, 문서)를 서버로 보내고, 충돌은 `updatedMs`로 가린다. 저장소와 화면 코드는 바꾸지 않는다. 문서는 `profileId`를 담아 프로필별로 나눌 수 있다.
