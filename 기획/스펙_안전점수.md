# 안전점수 모델 스펙 v0.2 (초안)

작성일: 2026-11-01
담당: 안전점수 API + POC
상태: 팀 합의 전 초안. "가안" 표시된 수치는 실차 데이터로 보정 전까지 임시값.

## 1. 목적과 범위

- 주행 세션 동안 들어오는 차량 신호를 받아 **이벤트(급가속, 급제동, 깜빡이 없는 차선변경)를 검출**하고, 세션이 끝나면 **세션 점수**를 돌려준다.
- 검출한 이벤트는 **즉시 밖으로 내보내** 주행 중 음성 피드백에 쓴다. 어떤 이벤트에 언제 말할지는 4-5절 규칙을 따른다.
- 세션이 **주행으로 인정되는 순간**(3-1)에도 알림을 내보낸다. 이 알림에는 인정 전에 생긴 이벤트가 전부 들어 있어, 보상 레이어는 인정 전 이벤트를 놓치지 않는다.
- MVP 필수 지표 3개: 급가속, 급제동, 방향지시등(깜빡이 없는 차선변경).
- 이 문서는 "무엇을 어떻게 잴지"만 정한다. 캐릭터, 경험치, 성장은 이 문서 범위 밖이다. 외부 모듈이 세션 결과를 받아 처리한다.

### 설계 원칙
1. **가점이 아니라 감점.** 기본 100점에서 위험 행동마다 깎는다. 깜빡이를 켜는 행동 자체에 점수를 주지 않는다. 그래야 어뷰징이 성립하기 어렵다.
   - **안전점수는 감점 위주로 하고, 각각의 요소를 잘 지켰을 때는 미션 완료 등의 외부 요소로 보상한다.** 안전점수 엔진은 "나쁜 행동의 빈도"만 재고, 보상은 그 결과를 읽는 쪽(외부 모듈)이 결정한다. 점수 엔진 안에 가점이나 경험치 배수는 두지 않는다.
   - T맵 운전점수, 현대 블루링크 안전운전 점수, 테슬라 Safety Score 모두 감점식 또는 위험 빈도식.
   - 미션의 예: "이번 세션 급제동 0회", "감점 없이 10km 주행", "이번 세션 깜빡이 100% 매칭", 연속 세션 스트릭. 모두 "행동을 해서"가 아니라 "위험 행동을 안 해서" 달성하는 미션이라 어뷰징 여지가 작다.
2. **거리로 정규화.** 장거리 운전자가 불리하지 않도록 감점은 구간당 횟수로 환산한다. (예: 10km당 n회)
3. **입력 추상화.** 신호가 Vehicle SDK에서 오든, 표준 AAOS API에서 오든, 테스트용 가짜 데이터에서 오든 같은 인터페이스로 들어온다.
4. **못 재는 건 안 잰다.** 주변 차량 간격, 현재 차선, 도로 곡률은 데이터가 없으므로 지표에서 제외하고, 대리 지표에는 이름에 "추정(EST)"을 붙인다.

### 2-1. 전처리

- **리샘플 간격 Δt = 100ms.** 모든 신호를 100ms 격자로 리샘플한다. 격자 사이에 콜백이 없으면 **마지막 값 유지(ZOH)**. 브레이크·조향각·방향지시등·기어는 "변경 시 콜백"이라 값이 안 바뀌면 콜백이 없고, 그 동안은 마지막 값이 맞다. 속도만은 주기 구독이라 콜백이 끊기면 진짜 끊긴 것이다(2-2).
- **속도 평활**: 리샘플된 speed에 **후행(trailing)** 3포인트 이동평균(현재와 직전 두 샘플). 중앙 정렬은 쓰지 않는다. 실시간 판정이라 미래 샘플을 쓸 수 없기 때문이다.
- **가속도 a**: "지금 속도 − 1초 전 속도"를 1초로 나눈 값 [m/s²]. 식으로 쓰면 `a(t) = (v(t) - v(t - 1.0s)) / 1.0s`. 0.1초마다 새로 구한다. 여기서 "1초 구간(time window)"은 지금부터 과거 1초까지의 시간 범위를 말한다. 4절의 가속·감속 판정은 전부 이 값 하나로 한다.
- **거리**: tripDistance가 있으면 그 증분을 쓴다. 없으면 `Σ max(v, 0) × Δt`. 후진 구간(3-2)은 거리에 넣지 않는다.
- **링버퍼**: 리샘플된 신호를 최근 30초 보관.

### 2-2. 신호 유실·지연

- speed는 주기 구독(2절)이라 정속 주행 중에도 콜백이 온다. 그런데도 speed 콜백이 **5초 이상** 없고 마지막 `|v| > 0.5 m/s`(후진 포함)이면 그 구간을 **stale**로 표시한다. (speed = 0 근처에서 콜백이 안 오는 건 정상 정차로 본다. 변경 시 콜백인 다른 신호에는 stale 개념을 적용하지 않는다.)
- stale 구간을 **가로지르는 1초 구간**은 a(t) 계산에서 제외한다. 콜백 재개 후 **1.0초** 동안도 제외한다. 재개 시 생기는 계단이 급가속·급제동으로 잡히지 않게 하기 위함.
- stale 구간은 거리 적분에도 넣지 않는다(tripDistance가 있으면 그 값을 믿는다).
- brakePedal "구간 안에 눌림"은 "구간 안에 콜백이 왔는지"가 아니라 "구간 안의 리샘플 값 중 하나라도 true였는지"다.

## 3. 세션 정의

### 3-1. 시작·종료

- **시작**: gear가 P 이외이고 `v > 1.0 m/s`가 처음 관측된 시점. gear를 못 받으면 `v > 1.0 m/s`가 5초 이상 지속된 시점. 후진은 v가 음수라 후진만 하는 이동(예: 후진 출차 뒤 바로 정차)은 세션을 시작하지 않는다.
- **종료**: 다음 둘 중 먼저 오는 것. (1) `|v| < 0.3 m/s`가 **3분** 연속 지속. 종료 시각은 그 3분의 **시작 시각**으로 기록한다(정차 3분은 세션 시간에 넣지 않는다). (2) 시동 OFF: 표준 AAOS `IGNITION_STATE`가 OFF로 바뀌는 시점. 이 속성을 서드파티 앱이 읽을 수 있는지는 미확인(9-2)이며, 안 되면 (1)만 쓴다. 시연 빌드는 (1)의 3분을 10초로 줄인 설정을 쓴다. (1)의 3분은 원격으로 조정할 수 있다(6-1).
- **앱 프로세스 종료**: POC에서는 진행 중 세션을 **폐기**한다. 부분 세션 보존은 POC 범위 밖이다.
- **최소 유효 세션 = 주행 인정 조건**: 거리 1km 이상 그리고 3분 이상. 둘 다 처음 충족되는 순간 세션이 **인정됨** 상태가 되고, 엔진은 그 즉시 `lifecycle` Flow로 `Validated`를 내보낸다(6절). 이 알림에는 **인정 전에 검출된 이벤트 목록 전체**가 들어 있다. 인정 전 이벤트도 점수·횟수에 똑같이 들어가며, 보상 레이어는 이 알림을 받은 뒤부터 실시간 이벤트를 따라가면 된다.
- 끝까지 인정되지 못한 세션(짧은 이동)은 `Validated` 없이 종료되고 `valid = false`로 점수를 내지 않는다. 그동안의 이벤트는 `SessionResult.events`에 남기지만 집계에는 쓰지 않는다.
- 세션 상태는 세 가지다: **시작됨(미인정) → 인정됨 → 종료**. 음성 피드백(4-5)은 인정 여부와 무관하게 시작 직후부터 실시간으로 동작한다.

### 3-2. 기어별 검출 규칙

검출은 **켬/끔 하나**로만 제어한다. 검출기마다 다른 조건을 두지 않는다.

| 상태 | 검출 | 거리 집계 |
|---|---|---|
| gear = P | 끔 | - |
| gear = R, 또는 (gear UNKNOWN이고 v < 0) = **후진 구간** | 끔 | 제외 |
| 후진 구간이 끝난 뒤 2.0초 | 끔 | 포함 |
| 그 외 (D, N, UNKNOWN에서 v ≥ 0) | 켬 | 포함 |

- 후진 직후 2.0초를 끄는 이유: 전·후진 전환 시 속도 부호가 뒤집히며 생기는 계단이 급가속으로 잡히는 것을 막기 위함.
- N은 D와 동일하게 판정한다. N에서는 바퀴에 동력이 가지 않아 페달 급가속이 물리적으로 불가능하고 내리막 중력 가속도 어느 후보 임계값(4-0-1)에 못 미치므로, 급가속만 따로 끄는 규칙은 두지 않는다. 급제동과 차선변경은 N에서도 그대로 잡힌다.

## 4. 이벤트 검출 규칙

### 4-0. 공통 정의

4절 전체에서 같은 뜻으로 쓰는 말을 먼저 정한다.

- **가속도 a**: 2-1절에서 정한 값. "지금 속도 − 1초 전 속도"를 1초로 나눈 것. 가속이면 양수, 감속이면 음수. 0.1초마다 새로 구한다. 단위는 m/s²로 쓰고, km/h/s는 괄호 안에 참고로만 적는다. (10 km/h/s ≈ 2.78 m/s²)
- **이벤트**: 어떤 조건(예: "가속도가 A1 이상")이 **끊기지 않고 이어진 한 덩어리**. 조건이 처음 성립해서 깨질 때까지가 이벤트 하나이고, 이것을 1회로 센다.
- **지속**: 조건이 **0.3초(연속 3번의 측정)** 이상 이어져야 이벤트로 인정한다. 센서 값이 한 번 튄 것을 이벤트로 세지 않기 위해서다.
- **쿨다운**: 이벤트가 끝난 뒤 **3초 안에** 같은 조건이 다시 성립하면 새 이벤트로 세지 않고 직전 이벤트에 붙인다. 한 번의 급제동이 중간에 살짝 풀렸다가 다시 잡히는 것을 두 번으로 세지 않기 위해서다. 쿨다운은 급가속과 급제동에 각각 따로 적용한다.
- **심각도**: 이벤트가 **얼마나 셌는지**. 그 이벤트 동안 가속도가 가장 컸던 순간의 값으로 정한다. 예를 들어 급제동 이벤트 중 감속이 가장 심했던 순간이 초당 15 km/h였다면, 그 이벤트의 심각도는 15 km/h/s다. 심각도 단계 수와 분기 기준 미정. (4-0-1에서 논의).
- **기어**: 4-1, 4-2, 4-3 모두 3-2의 켬/끔을 먼저 적용한다. 꺼져 있으면 아래 조건을 보지 않는다.

### 4-0-1. 임계값·심각도 기준 비교 (논의 필요)

이 절은 팀이 정해야 할 두 가지, **1단계 임계값**과 **심각도(2단계) 방식**을 다룬다. 급가속·급감속 1단계 임계값으로 쓸 수 있는 공개 기준은 둘이다. **이 문서는 아직 어느 쪽도 채택하지 않았다.**

| 항목 | 한국교통안전공단 위험운전행동 기준 | 현대 블루링크 안전운전 점수 리포트 기준 |
|---|---|---|
| 급가속 | 초당 11 km/h 이상 가속 (≈ 3.06 m/s²) | 1초 이내 10 km/h 이상 가속 (≈ 2.78 m/s²) |
| 급출발 | 정지 상태(5 km/h 이하)에서 초당 11 km/h 이상 가속. 별도 항목 | 별도 항목 없음 (리포트 화면에는 급가속·급감속만) |
| 급감속 | 초당 7.5 km/h 이상 감속 (≈ 2.08 m/s²) | 1초 이내 13 km/h 이상 감속 (≈ 3.61 m/s²) |
| 급정지 | 초당 7.5 km/h 이상 감속해 5 km/h 이하로 정지. 별도 항목 | 별도 항목 없음 |
| 급진로변경 | 30 km/h 이상에서 가감속과 좌우 방위각 변화(6° 이상)를 동반 | 없음 |
| 과속 | 제한속도 20 km/h 초과. 3분 이상이면 장기과속 | 리포트 화면에 "제한속도 초과" 항목 있음, 수치 없음 |
| 그 밖 | 급회전, 급U턴, 급앞지르기 등 총 11개 항목 | 없음 |
| 적용 대상 | 사업용 차량 디지털운행기록장치(DTG) 분석 기준 | 블루링크 가입 승용차 운전자 |
| 2단계 | 없음 (횟수만 집계) | 없음 (횟수만 집계, 항목별 등급 표시) |
| 출처 신뢰도 | 공식 기준이나 **원문 대조 전**(기억에 의존). 운행기록분석시스템(eTAS) 안내 자료에서 확인 필요 | 2023년 리포트 화면 캡처. 현대 공식 페이지에는 수치 없음. **현재도 같은지 미확인** |

두 기준 체감 차이: 급가속은 거의 같고(10 vs 11 km/h/s), 급감속은 블루링크가 훨씬 둔하다(13 vs 7.5 km/h/s). 공단 기준이면 보통 세기의 제동도 자주 잡히고, 블루링크 기준이면 명확히 세게 밟은 것만 잡힌다.

논의 포인트:
- **블루링크 채택의 장점**: 공모전 주최사의 자사 기준과 같은 정의라 "블루링크 점수와 호환, 향후 연동 가능"이라고 쓸 수 있다. 승용차 운전자 대상 기준이라 우리 타깃과 맞는다.
- **공단 채택의 장점**: 공식 문서로 출처를 댈 수 있고 항목이 11개라 확장 여지가 있다. 다만 사업용 차량 기준이라 승용차 체감과 다를 수 있고, 급감속이 예민해 억울한 감점이 늘 수 있다.

**심각도(1단계·2단계) — 미정.** 2단계를 둘지, 둔다면 경계와 감점 가중을 어떻게 할지 결정 필요. 위 표대로 공단 기준과 블루링크 기준 모두 단계 없이 횟수만 센다.

| 후보 | 내용 | 장점 | 단점 |
|---|---|---|---|
| (a) 단계 없음 | 횟수만 센다 | 두 공개 기준과 같은 방식. 가장 단순하고 설명하기 쉽다 | 살짝 넘긴 것과 패닉 브레이크가 같은 1회 |
| (b) 2단계 + 감점 가중 | 2단계 경계 = 1단계 × 1.5, 감점 1.5배 | 세게 밟은 것에 더 깎는다 | 경계와 배율 모두 근거 없는 가안. 실차 데이터로 뒷받침해야 함 |
| (c) 2단계 기록만 | 경계는 (b)와 같되 감점은 단일. 심각도는 음성 톤 차등과 리포트 표시에만 | 점수는 (a)와 같아 호환 주장 유지, 반응은 차등 가능 | 파라미터는 (b)만큼 늘어남 |

아래 4-1, 4-2의 심각도 행과 5-1의 2단계 열, 7-1 시나리오의 "2단계" 표기는 **후보 (b)를 가정한 예시**다. (a)로 결정되면 그 행·열을 지우고, (c)면 5-1 가중만 지운다.

### 4-1. 급가속 (HARSH_ACCEL)

1단계 임계값 **A1 결정 필요**. 후보는 4-0-1의 두 기준: 공단 11 km/h/s (3.06 m/s²) 또는 블루링크 10 km/h/s (2.78 m/s²). 2단계 임계값 A2는 미정(4-0-1). 아래 표의 심각도 행은 후보 (b) 가정.

| 항목 | 가안 |
|---|---|
| 조건 | `a(t) ≥ A1` |
| 지속 / 쿨다운 | 공통 정의 |
| 출발 가속 | 이벤트가 시작된 1초 구간의 **시작 속도** `v(t − 1.0s) < 1.0 m/s`이면 `fromStop = true` 플래그만 붙인다. (이벤트 시작 시점 t의 속도는 이미 가속 중이라 1.0을 넘는다.) **별도 타입(HARSH_START)은 두지 않는다.** 감점은 HARSH_ACCEL과 동일. |
| 심각도 | 1단계: `A1 ≤ max a < A2` / 2단계: `max a ≥ A2` |

### 4-2. 급제동 (HARSH_BRAKE)

1단계 임계값 **B1 결정 필요**. 후보는 4-0-1의 두 기준: 공단 7.5 km/h/s (2.08 m/s²) 또는 블루링크 13 km/h/s (3.61 m/s²). 두 후보 차이가 커서(약 1.7배) 체감이 크게 달라지는 항목이다. 참고로 텔레매틱스 업계 관행은 0.3~0.4g (2.9~3.9 m/s², 추정). 2단계 임계값 B2는 미정(4-0-1). 아래 표의 심각도 행은 후보 (b) 가정.

| 항목 | 가안 |
|---|---|
| 조건 | `a(t) ≤ -B1` **그리고** 같은 1초 구간 안의 brakePedal 리샘플 값 중 하나라도 true |
| 지속 / 쿨다운 | 공통 정의 |
| 제외 | 1초 구간의 **끝 속도** `v(t) < 2.0 m/s`인 구간 (정차 직전 미세 조정) |
| 심각도 | 1단계: `B1 ≤ max |a| < B2` / 2단계: `max |a| ≥ B2` |

brakePedal 조건을 넣는 이유: 내리막 엔진브레이크, 회생제동만으로 생기는 감속을 급제동으로 오탐하지 않기 위함. 통상 회생제동 최대치는 2~3 m/s² 수준이라, B1을 블루링크 후보(3.61)로 잡으면 페달 조건 없이도 오탐이 드물지만 공단 후보(2.08)로 잡으면 이 조건이 필수가 된다. 브레이크 신호는 Boolean(눌림 여부)뿐이라 세기는 알 수 없다.

### 4-3. 깜빡이 없는 차선변경 (LANE_CHANGE_NO_SIGNAL)

데이터 한계: 차선 위치, 도로 곡률 없음. 조향각 패턴으로 "차선변경으로 추정되는 조작"을 잡는다.

**(a) 차선변경 추정 (LANE_CHANGE_EST)**

| 항목 | 가안 |
|---|---|
| 전제 | `v ≥ 8.3 m/s (30 km/h)`, 3-2 검출 켬 상태 |
| 기준선 θbase | **첫 이탈 시점 t0에서 고정.** t0 직전 3초 조향각의 중앙값. 패턴 판정이 끝나거나 취소될 때까지 갱신하지 않는다. (매 샘플 갱신하면 커브 출구에서 오탐.) |
| 1단계 이탈 | `|θ(t) - θbase| ≥ θ1`이 되는 첫 시점 = t0. 방향 d = 부호. |
| 커브 판정 (우선) | t0 이후 같은 방향 이탈이 **3.0초 이상** 유지되면 **커브**로 확정하고 패턴을 취소한다. 이후 반대 조향은 새 패턴의 후보가 된다(새 t0, 새 θbase). |
| 2단계 이탈 | 커브로 확정되기 전에, t0부터 **5.0초 안에** 반대 방향으로 `|θ(t) - θbase| ≥ θ1` |
| 복귀 | 2단계 이탈 후 **3.0초 안에** `|θ(t) - θbase| < θ0` → LANE_CHANGE_EST 확정, 시각 = t0 |
| 취소 | 위 시간 안에 다음 단계로 못 가면 패턴 취소 |
| θ1 (속도별, 속도는 t0 시점 값) | **에뮬레이터용(현재 구현값)**: `30 ≤ v_kmh < 60`: 25° / `60 ≤ v_kmh < 90`: 15° / `v_kmh ≥ 90`: 10°. 핸들 회전각 스케일이며 에뮬레이터가 카드 값을 그대로 주는 것이 확인됐다. **실차용**: AAOS 정의가 앞바퀴 각이라 위 값의 약 1/14(승용차 스티어링비 13~16:1)인 2° / 1° / 0.7° 수준으로 추정되지만 실차 데이터가 없어 미정. 엔진에서는 θ1·θ0을 핸들 각 기준으로 두고, 조향비 `steeringRatio`(에뮬레이터 1.0, 실차 추정 13~16)로 나눈 값을 입력 조향각과 비교한다. θ1 구간과 조향비는 원격으로 조정할 수 있다(6-1). |
| θ0 | 5° |
| 쿨다운 | 확정 후 2.0초 동안 새 t0를 잡지 않는다 |

**(b) 깜빡이 매칭**

LANE_CHANGE_EST 확정 시, t0 기준으로 아래 순서로 판정한다. SDK에 비상등 값이 없으므로, 비상등을 켰을 때 TurnSignal에 무엇이 오는지(OFF인지, 좌우가 번갈아 오는지)는 에뮬레이터에서 확인한 뒤 규칙을 추가한다(9-2).

| 순서 | 조건 | 결과 이벤트 |
|---|---|---|
| 1 | `t0 - 3.0s ~ t0 + 0.5s` 사이에 d 방향 turnSignal이 ON이 되고, 그 ON이 **1.0초 이상** 연속 유지 | **LANE_CHANGE_SIGNALED** (감점 0, 이벤트 목록에는 포함) |
| 2 | 같은 구간에 d 방향 ON은 있으나 1.0초 미만 | **LANE_CHANGE_NO_SIGNAL** |
| 3 | 같은 구간에 반대 방향 ON (1.0초 이상) | **LANE_CHANGE_WRONG_SIGNAL** |
| 4 | 그 외 | **LANE_CHANGE_NO_SIGNAL** |
| - | turnSignal ON인데 LANE_CHANGE_EST 없음 | 이벤트 없음, 변동 0 |

LANE_CHANGE_SIGNALED를 이벤트 목록에 넣는 이유: 미션 "깜빡이 100% 매칭"의 분모(전체 차선변경 추정 횟수)가 필요하기 때문.

**(c) 연속 급차선변경 (WEAVING_EST, 선택 · POC 제외)**

15초 안에 LANE_CHANGE_EST(SIGNALED 포함)가 방향을 바꿔 가며 3회 이상이면 1회 추가 감점. 이름에 "칼치기"를 쓰지 않는다(간격을 모르므로).

### 4-4. 과속 (SPEEDING, 선택 · POC 제외 · 내비 안내 중만)

| 항목 | 가안 |
|---|---|
| 조건 | `v_kmh > max(speedLimit × 1.1, speedLimit + 10)`, 10초 이상 지속 |
| 집계 | 초과 지속 시간(초)을 누적. 10km당 60초마다 1회로 환산 |
| 데이터 없을 때 | speedLimit 미수신 세션은 SPEEDING 감점 0으로 처리한다. |
| 세부 점수 | SPEEDING은 세션 점수에만 합산하고 5-2 세부 점수에는 넣지 않는다 |

### 4-5. 주행 중 실시간 음성 피드백 (POC 포함)

목적은 "방금 그 행동을 캐릭터가 알아챘다"를 운전자가 즉시 느끼게 하는 것이다. 점수를 말하지 않고, 화면을 바꾸지 않고, **짧은 음성 한 마디**만 낸다. Pleos 주행 안전 가이드가 주행 중 시각 요소는 최소화하고 음성 연계를 권장하므로 규정에도 맞는다.

**역할 분담**

| 역할 | 위치 | 내용 |
|---|---|---|
| 이벤트 방출 | `:engine` | 이벤트가 **확정되는 순간** `events` Flow로 내보낸다. 급가속·급제동은 지속(0.3초) 충족 시점, 차선변경 계열은 복귀 확정 시점. 이때 심각도는 잠정값이고 최종값은 `SessionResult`에 담긴다. 세션 인정 전에도 내보낸다(음성은 인정과 무관). |
| 발화 결정 | `:engine` (`FeedbackDecider`, 순수 로직) | 아래 규칙으로 "지금 말할지, 무엇을 말할지"를 정한다. JUnit으로 검증 가능. |
| 재생 | `:app` (`VoicePlayer`) | 녹음 클립 또는 TTS 재생, 오디오 포커스 처리, 사용자 끄기 설정. |

**발화 시점 규칙**

| 이벤트 | 발화 시점 | 이유 |
|---|---|---|
| HARSH_BRAKE | 이벤트 종료 후 `a(t) > -1.0 m/s²`가 **1.5초** 유지된 뒤 | 긴급 상황 한가운데서 말 걸지 않는다. 방어 운전이었어도 상황이 끝난 뒤 듣는 건 부담이 적다 |
| HARSH_ACCEL | 이벤트 종료 후 **1.0초** | 가속 중 발화는 묻힌다 |
| LANE_CHANGE_NO_SIGNAL / WRONG_SIGNAL | 확정 즉시 | 확정 자체가 조향 복귀 뒤라 이미 안정 상태 |
| LANE_CHANGE_SIGNALED | **세션 첫 1회만** 발화, 이후 침묵 | 매번 칭찬하면 깜빡이를 "말 듣기 위해" 켜는 행동을 유도. 첫 1회는 "알아보고 있다"는 신호용 |
| 세션 시작 | `v > 1.0 m/s` 첫 관측 + 3초 | 인사 한 마디. 실제로 출발했음을 확인한 뒤 |
| 세션 종료 | 발화 없음 | 정차 3분 뒤라 운전자가 없을 수 있음. 결과는 정차 중 화면으로 |

**빈도 제한 (값은 기획이 정한다. 엔진은 변수로만 받는다 — `EngineConfig`. 원격 조정은 6-1)**

- `F_same` **같은 타입 최소 간격**: 같은 타입 발화 사이에 최소 F_same 초를 띄운다. 그 사이 같은 타입 이벤트는 발화 없이 기록만.
- `F_all` **전체 최소 간격**: 타입과 무관하게 발화 사이에 최소 F_all 초를 띄운다. 급제동 직후 차선변경이 와도 하나만 말한다. 우선순위: HARSH_BRAKE > LANE_CHANGE_NO_SIGNAL > HARSH_ACCEL > 나머지.
- `N_max` **세션당 타입별 발화 상한**: 넘으면 그 타입은 세션 끝까지 침묵하고, 요약은 정차 후 화면에서. 잔소리로 느껴지는 지점을 넘지 않기 위한 변수.
- 후진 구간, stale 구간, 세션 시작 전에는 발화하지 않는다.

**문구 원칙**

- 2초 안에 끝나는 한 문장. 수치·점수·"감점" 같은 단어를 쓰지 않는다.
- 비난이 아니라 **캐릭터의 반응**으로 쓴다. 운전자가 "혼났다"가 아니라 "얘가 놀랐구나"로 받게. 방어 운전으로 급제동한 사람도 억울하지 않을 톤.
- 같은 타입에 문구 3개 이상을 두고 돌려 쓴다. 같은 말 반복은 잔소리 체감을 키운다.

**재생 (Android 쪽)**

- **녹음 클립만 쓴다.** Pleos TTS SDK는 신청이 안 되고, 에뮬레이터를 띄워 확인한 결과 시스템 TTS 엔진도 없다(2026-11-03). 시연 영상과 제출 APK 모두 클립. 캐릭터 목소리는 어차피 녹음이 자연스럽고, 문구가 고정돼 있으니 클립 20개 안쪽이면 충분하다.
- 오디오 포커스: `AudioManager`에 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`로 요청해 음악은 줄이고 끝나면 돌려준다. Pleos 오디오 포커스 가이드와 "TTS/음성 안내 선행 묵음 가이드"를 따른다. 내비 안내 음성이 나오는 중이면 **포커스를 못 받으므로 그 발화는 버린다**(큐에 쌓지 않는다. 늦게 나오는 지적은 맥락을 잃는다).
- 사용자 설정: 음성 끄기 토글 필수. 설정 변경은 정차 중에만(주행 중 UI 제한).
- 긍정 피드백(10km 무이벤트, 미션 달성)은 미션 모듈이 "말할 내용"을 주면 같은 `VoicePlayer`가 재생한다. 빈도 제한은 같은 큐를 공유한다. POC에서는 자리만 둔다.

## 5. 점수 계산

### 5-1. 세션 점수 (0~100)

```
D             = max(세션 거리 km, 10)                          -- 10km 미만 세션은 10km로 간주 (짧은 세션 과대 감점 방지)
정규화 횟수_i  = 이벤트 횟수_i × (10 / D)
감점_i        = min(정규화 횟수_i × 단위감점_i, 상한_i)         -- 2단계 감점 가중은 미정(4-0-1). 아래 표의 2단계 열은 후보 (b) 가정
세션 점수     = round_half_up(max(0, 100 - Σ 감점_i))         -- 소수 첫째 자리에서 반올림, .5는 올림
```

| 이벤트 | 단위감점 (10km당 1회, 1단계) | 2단계 (후보 (b) 가정, 미정) | 상한 | 비고 |
|---|---|---|---|---|
| HARSH_ACCEL | 4 | 6 | 30 | fromStop 플래그는 감점에 영향 없음 |
| HARSH_BRAKE | 5 | 7.5 | 35 | 급제동이 급가속보다 사고 상관이 높다는 가정으로 가중 (추정) |
| LANE_CHANGE_NO_SIGNAL | 6 | - | 30 | 심각도 없음 |
| LANE_CHANGE_WRONG_SIGNAL | 6 | - | (NO_SIGNAL과 합산해 30) | 반대 방향 신호는 위험 행동 |
| LANE_CHANGE_SIGNALED | 0 | - | - | 집계용 |
| WEAVING_EST | 8 | - | 16 | 선택, POC 제외 |
| SPEEDING (60초당) | 5 | - | 25 | 선택, POC 제외 |

상한을 두는 이유: 산길 연속 커브 같은 오탐 구간에서 점수가 바닥까지 떨어지는 것을 막기 위해.

단위감점과 상한은 원격으로 조정할 수 있다(6-1). 정규화 거리 10km는 조정하지 않는다.

### 5-2. 세부 점수 (화면 표시용)

- 가속 점수 = round_half_up(100 - 감점(HARSH_ACCEL))
- 제동 점수 = round_half_up(100 - 감점(HARSH_BRAKE))
- 매너 점수 = round_half_up(100 - 감점(NO_SIGNAL + WRONG_SIGNAL + WEAVING_EST))
- 세션 점수는 세 세부 점수의 평균이 아니라 5-1의 합산식. 세부 점수는 설명용.
- 세부 점수 옆에 **이벤트 횟수도 같이 표시**한다. 10km 미만 세션은 D = 10으로 고정돼 점수가 둔하게 움직이므로, 운전자에게는 "급제동 2회"가 "제동 점수 90"보다 직관적이다. 횟수는 `SessionResult.events`에서 센다.

### 5-3. 경험치

- 경험치는 안전점수 엔진이 계산하지 않는다. 미션 완료 등 외부 요소로 지급하며, 미션 모듈은 `SessionResult` **전체**(세션 점수, 세부 점수, 이벤트 목록, 거리)를 그대로 받아 달성 여부를 판단한다. 엔진이 정보를 골라 주지 않는다.
- 세션 점수에 따른 경험치 배수는 두지 않는다.

## 6. 모듈 인터페이스 (POC 기준)

**시계 규칙.** 엔진은 시스템 시계를 직접 읽지 않는다. 시간은 두 경로로만 들어온다. (1) 모든 `VehicleSignal`의 `timestampMs`, (2) 호스트가 주기적으로 부르는 `onTick(nowMs)`. 차가 서면 "변경 시 콜백"인 신호가 끊기므로, 3절의 "정차 3분 종료"와 4절의 쿨다운·"5초 안에" 같은 제한 시간 만료는 `onTick`이 없으면 영영 판정되지 않는다. Android에서는 1초마다, JUnit에서는 JSON 시나리오의 타임스탬프를 그대로 넣는다. 그래서 S10(2분), S11(10km + 정차 3분) 같은 긴 시나리오도 JUnit에서 밀리초 안에 돈다.

**세션 결과는 두 경로로 나간다.** 정차 3분으로 자동 종료되면 `sessions` Flow로 흘러나오고, 호스트가 강제로 끝내면(앱 종료 직전 등) `endSessionNow()`가 같은 결과를 돌려준다. 둘 다 `SessionResult` 하나.

**세션 상태 변화는 `lifecycle` Flow로 나간다.** `Started`(출발 확인), `Validated`(주행 인정, 그때까지의 이벤트 목록 포함), `Ended`(종료, 결과 포함). 보상 레이어는 `Validated`를 받기 전까지는 `events`를 무시해도 된다. `Validated`에 그 이벤트가 전부 들어 있기 때문이다. 받은 뒤부터는 `events`를 실시간으로 따라간다.

```kotlin
// 입력: 출처와 무관한 신호
sealed interface VehicleSignal {
    val timestampMs: Long
    data class Speed(override val timestampMs: Long, val mps: Float) : VehicleSignal        // 후진 시 음수일 수 있음(미확인)
    data class BrakePedal(override val timestampMs: Long, val pressed: Boolean) : VehicleSignal   // SDK는 Boolean만 준다
    data class SteeringAngle(override val timestampMs: Long, val degrees: Float) : VehicleSignal
    data class TurnSignal(override val timestampMs: Long, val state: TurnSignalState) : VehicleSignal
    data class Gear(override val timestampMs: Long, val gear: GearState) : VehicleSignal
    data class TripDistance(override val timestampMs: Long, val meters: Float) : VehicleSignal
    data class SpeedLimit(override val timestampMs: Long, val kmh: Int?) : VehicleSignal
}

enum class TurnSignalState { OFF, LEFT, RIGHT }   // SDK 값 그대로. 비상등 표현은 에뮬레이터 확인 뒤 결정
enum class GearState { P, R, N, D, UNKNOWN }

enum class EventType {
    HARSH_ACCEL, HARSH_BRAKE,
    LANE_CHANGE_SIGNALED, LANE_CHANGE_NO_SIGNAL, LANE_CHANGE_WRONG_SIGNAL,
    WEAVING_EST, SPEEDING            // POC 제외
}

// 출력: 이벤트와 세션 결과
data class DrivingEvent(
    val type: EventType,
    val severity: Int,            // 1 or 2 (차선변경 계열은 항상 1)
    val startMs: Long, val endMs: Long,
    val speedMps: Float,          // 이벤트 시작 시 속도
    val fromStop: Boolean = false, // HARSH_ACCEL 전용
    val detail: String            // 디버그용 ("max a=-2.4m/s², pedal=72%")
)

data class SessionResult(
    val startMs: Long, val endMs: Long,
    val distanceKm: Float,
    val events: List<DrivingEvent>,          // SIGNALED 포함 (미션 분모용)
    val score: Int,                          // 0~100, round_half_up
    val accelScore: Int, val brakeScore: Int, val mannerScore: Int,
    val valid: Boolean,                      // 최소 유효 세션 조건 충족 여부
    val paramsVersion: Int                   // 이 세션에 쓴 원격 조정 수치의 버전. 내장 기본값이면 0 (6-1)
    // 경험치는 여기서 내지 않는다. 미션 모듈이 이 결과를 읽어 지급한다.
)

data class EngineConfig(                     // 4·5절 수치. 임계값은 기본값을 두지 않는다. 아래 Presets 중 하나를 넘겨 시작한다
    val resampleMs: Long = 100,
    val accelThreshold: Float, val accelSevere: Float,     // A1, A2 (m/s²). 4-0-1 후보 중 선택한 값
    val brakeThreshold: Float, val brakeSevere: Float,     // -B1, -B2 (m/s²)
    val persistMs: Long = 300, val cooldownMs: Long = 3000,
    val sessionEndIdleMs: Long = 3 * 60_000, // 시연 빌드는 10_000
    val minValidKm: Float = 1f, val minValidMs: Long = 3 * 60_000,
    val paramsVersion: Int = 0,              // 원격 조정 수치의 버전 (6-1)
    // θ1 속도 구간, θ0, 조향비 steeringRatio(에뮬레이터 1.0, 실차 추정 13~16. θ1·θ0 을 나눠 입력 조향각과 비교),
    // 조향각 부호 반전 steeringInverted, 매칭 허용 시간 등은 laneChange(LaneChangeConfig) 안에
)

// 임계값 후보 프리셋 (4-0-1). 팀 결정 전에는 둘 다로 테스트를 돌린다
object Presets {
    val KOTSA    = EngineConfig(accelThreshold = 3.06f, accelSevere = 4.59f, brakeThreshold = -2.08f, brakeSevere = -3.12f)  // 공단 11 / 7.5 km/h/s
    val BLUELINK = EngineConfig(accelThreshold = 2.78f, accelSevere = 4.17f, brakeThreshold = -3.61f, brakeSevere = -5.42f)  // 블루링크 10 / 13 km/h/s
}

interface SafetyScoreEngine {
    // 입력
    fun onSignal(signal: VehicleSignal)
    fun onTick(nowMs: Long)                   // 호스트가 1초마다. 시간 기반 판정(세션 종료, 제한 시간 만료, 쿨다운)은 여기서만 진행

    // 출력
    val events: Flow<DrivingEvent>            // 이벤트 확정 즉시 방출 (4-5). severity는 잠정값. 세션 인정 전에도 방출
    val lifecycle: Flow<SessionLifecycle>     // Started / Validated(인정 전 이벤트 전부 포함) / Ended
    val feedback: Flow<FeedbackCue>           // FeedbackDecider가 4-5 규칙을 통과시킨 발화만
    val sessions: Flow<SessionResult>         // 정차 3분으로 자동 종료된 세션
    fun endSessionNow(nowMs: Long): SessionResult?   // 강제 종료. 진행 중 세션이 없으면 null
    fun updateConfig(next: EngineConfig)      // 원격 조정 수치(6-1). 다음 세션 시작 때 적용, 진행 중 세션은 그대로
    fun currentPartialScore(): Int            // 주행 중 표시용 (선택)
}

// 세션 상태 (3-1). 최소 유효 세션 조건(1km·3분)이 충족되는 순간 Validated가 나간다
sealed interface SessionLifecycle {
    data class Started(val startMs: Long) : SessionLifecycle
    data class Validated(val atMs: Long, val eventsSoFar: List<DrivingEvent>) : SessionLifecycle   // 인정 전 이벤트 전부 포함
    data class Ended(val result: SessionResult) : SessionLifecycle                                 // sessions Flow와 같은 결과. 미인정이면 result.valid = false
}

// 음성 피드백 (4-5)
enum class CueType { SESSION_START, HARSH_BRAKE, HARSH_ACCEL, LANE_NO_SIGNAL, LANE_SIGNALED_FIRST, MILESTONE }
data class FeedbackCue(
    val type: CueType,
    val atMs: Long,               // 발화해야 할 시각 (급제동은 안정 후 1.5초 등, 지연이 반영된 값)
    val variant: Int,             // 같은 타입 문구 중 몇 번째 (돌려쓰기용)
    val sourceEvent: DrivingEvent?
)

// :engine 내부. 순수 로직이라 JUnit으로 빈도 제한을 검증한다
interface FeedbackDecider {
    fun onEvent(event: DrivingEvent, nowMs: Long): FeedbackCue?
    fun onTick(nowMs: Long): FeedbackCue?     // 급가속 지연 발화(종료 + 1.0초가 지난 첫 틱)와 세션 시작 인사는 틱에서 나온다
}

// :app. 클립 재생, 오디오 포커스, 끄기 설정
interface VoicePlayer {
    fun play(cue: FeedbackCue)                // 포커스를 못 받으면 버린다. 큐에 쌓지 않는다
}

// 신호 공급자: 구현체를 바꿔 끼운다
interface SignalSource {
    fun start(sink: (VehicleSignal) -> Unit)
    fun stop()
}

// :app (Android)        — PleosVehicleSdkSource(brake, steering, turnSignal, tripDistance)
//                         AaosCarPropertySource(speed, gear)   ← 속도 주입이 안 되면 POC에서 제외
//                         MergedSignalSource(여러 소스를 하나로)
//                         VoicePlayer(녹음 클립 우선, TTS 대체)
```

**모듈 분리.** `:engine`은 `kotlin("jvm")` 모듈이고 `kotlinx.coroutines`만 의존한다. Android 클래스(`Context`, `Car`, Pleos SDK)는 `:app`에서만 import한다. 이렇게 해야 1주차에 Android Studio 없이도 엔진을 만들고 돌릴 수 있고, 심사용 GitHub 저장소에서 "엔진 로직 + 테스트"가 따로 읽힌다.

**Pleos SDK 콜백을 `SignalSource`로 감싸기.** Pleos Vehicle SDK는 도메인 객체 → `registerXxx(listener)` → 콜백 패턴이고 결과는 `onComplete`/`onFailed`로 온다(반환 타입은 문서 미공개, 9절). `PleosVehicleSdkSource.start`에서 네 도메인을 register하고, 콜백마다 값을 `VehicleSignal`로 바꿔 `sink`에 넘긴다. `stop`에서 unregister 후 `Vehicle.release()`. 콜백이 끝나기 전에 release하지 말라는 주의가 문서에 있다.

### 6-1. 원격 조정 수치

엔진 수치 중 아래 표에 있는 것만 원격 콘텐츠 업데이트(#31)로 바꿀 수 있다. 표에 없는 수치와 판정 방식은 앱 코드에 들어 있어 스토어 업데이트로만 바뀐다(#33).

- 목록, 범위, 간격은 엔진 코드(`TunableParam`)에 정의한다. 이 절의 표는 코드와 같아야 한다.
- 목록, 범위, 간격을 바꾸려면 스토어 업데이트가 필요하다. 원격으로 바꾸는 것은 범위 안의 값뿐이다.

**적용 규칙**

- **세션 고정.** 엔진은 새 설정을 `updateConfig`로 받아 두었다가 다음 세션이 시작될 때 적용한다. 진행 중인 세션에는 적용하지 않는다. 세션 시작 전에 여러 번 받으면 마지막 것을 쓴다.
- **지난 기록 유지.** 수치가 바뀌어도 지난 세션의 점수는 다시 계산하지 않는다.
- **버전 기록.** `SessionResult.paramsVersion`에 그 세션에 쓴 수치의 버전을 남긴다. 버전은 그 수치가 들어 있던 콘텐츠 묶음의 `contentVersion`이다. 원격 수치 없이 앱 내장 기본값만 쓰면 0이다.
- **내장 기본값.** 아래 표의 기본값이다. 임계값의 기본값은 앱 설정에서 고른 프리셋(4-0-1)이다.
- **빠진 값.** 묶음에 없는 수치는 내장 기본값을 쓴다.
- **전부 아니면 전무.** 값 하나라도 범위, 간격, 관계 규칙을 어기면 받은 묶음 전체를 버리고 이전 묶음을 유지한다(#31). 값 하나만 빼고 적용하면 1단계 임계값이 2단계보다 커지는 것처럼 값끼리 어긋날 수 있다.

**값 형식**

원격 값은 콘텐츠 묶음 JSON의 `engine` 항목에 이름과 실제 값(예: `"brake1Kmhs": 13.0`)으로 보낸다. 켬·끔은 0·1로 쓴다.

- 허용 값은 `최솟값 + 간격 × k`(k는 0 이상 정수)다. 범위 밖이거나 간격에 맞지 않는 값(예: 간격 0.5에 7.3)은 거절한다.
- 앱이 모르는 이름이 있으면 거절한다. 새 수치는 `minAppVersion`으로 그 수치를 아는 앱에만 보낸다.
- 숫자는 따옴표 없이 쓴다. 숫자 자리에 따옴표 붙은 값(예: `"13"`)이 있으면 묶음 전체를 버린다. 엔진 수치뿐 아니라 묶음의 모든 숫자에 같다.
- 한 객체 안에 같은 이름이 두 번 있으면 묶음 전체를 버린다. 어느 값을 뜻했는지 알 수 없다.
- 간격은 기본값과 두 프리셋(공단·블루링크)이 모두 간격 위에 오도록 잡았다.

**원격 조정 수치**

아래 다섯 표가 원격으로 바꿀 수 있는 수치 전부다. "이름"은 JSON에 쓰는 이름이다.

*임계값 (4-0-1).* km/h/s로 받아 엔진에서 m/s²로 바꾼다. 공단·블루링크 기준이 km/h/s라 그대로 옮길 수 있다.

| 수치 | 이름 | 기본값 | 범위 (간격) |
|---|---|---|---|
| 급가속 1단계 A1 | `accel1Kmhs` | 프리셋 | 5.0~36.75 km/h/s (0.25) |
| 급가속 2단계 A2 | `accel2Kmhs` | 프리셋 | 5.0~36.75 km/h/s (0.25) |
| 급제동 1단계 B1 | `brake1Kmhs` | 프리셋 | 5.0~36.75 km/h/s (0.25) |
| 급제동 2단계 B2 | `brake2Kmhs` | 프리셋 | 5.0~36.75 km/h/s (0.25) |

- 프리셋 값(A1 / A2 / B1 / B2): 블루링크 10 / 15 / 13 / 19.5, 공단 11 / 16.5 / 7.5 / 11.25.
- 하한 5 km/h/s(약 1.4 m/s²)는 일상 주행의 가감속 수준이다. 이보다 낮으면 보통 출발·정지도 이벤트가 된다.
- 상한 36.75 km/h/s(약 1.04 g)는 승용차 최대 제동 수준이다.

*감점표 (5-1).*

| 수치 | 이름 | 기본값 | 범위 (간격) |
|---|---|---|---|
| 급가속 1·2단계 | `penaltyAccel`, `penaltyAccelSevere` | 4, 6 | 0~31.5점 (0.5) |
| 급제동 1·2단계 | `penaltyBrake`, `penaltyBrakeSevere` | 5, 7.5 | 0~31.5점 (0.5) |
| 깜빡이 없음·반대 깜빡이 | `penaltyLaneNoSignal`, `penaltyLaneWrongSignal` | 6, 6 | 0~31.5점 (0.5) |

- 단위감점 0은 그 항목의 감점을 끈다.
- 상한이 100점까지인 이유: 세션 점수가 100점 만점이라 100을 넘는 상한은 뜻이 없다. 상한이 100 이하라 세부 점수(5-2)도 음수가 되지 않는다.
- 지그재그와 과속은 POC 제외 항목이라 지금은 값을 바꿔도 점수에 영향이 없다.

*음성 발화 (4-5).*

| 수치 | 이름 | 기본값 | 범위 (간격) |
|---|---|---|---|
| F_same 같은 타입 최소 간격 | `feedbackSameTypeMinSec` | 90초 | 10~640초 (10초) |
| F_all 전체 최소 간격 | `feedbackAnyTypeMinSec` | 20초 | 5~320초 (5초) |
| N_max 세션당 타입별 상한 | `feedbackMaxPerType` | 3회 | 0~15회 (1) |
| 급제동 발화 전 안정 시간 | `brakeStableSec` | 1.5초 | 0~6.3초 (0.1초) |
| 급제동 안정 판정 가속도 | `brakeStableAccel` | −1.0 m/s² | −3.2~−0.1 m/s² (0.1) |
| 급가속 발화 지연 | `accelDelaySec` | 1.0초 | 0~6.3초 (0.1초) |
| 세션 시작 인사 지연 | `sessionStartDelaySec` | 3.0초 | 0~31.5초 (0.5초) |
| 깜빡이 첫 1회 칭찬 | `praiseFirstSignaled` | 켬(1) | 0·1 |

- F_all이 5초부터인 이유: 0이면 두 문구가 같은 시각에 겹친다(문구는 2초 이내).
- N_max는 모든 이벤트 타입에 같은 값을 쓴다. 0이면 세션 시작 인사만 남고 이벤트 발화와 첫 깜빡이 칭찬이 모두 꺼진다.
- 안정 판정 가속도가 0까지 가지 않는 이유: 판정이 `a > 값`이라 0이면 정차 중(a = 0)에 끝까지 발화하지 않는다.
- 타입별 문구 개수는 열지 않는다. 녹음 클립 수에 묶여 있어 리소스 패치와 함께 정해야 한다 `[미정]`.

*차선변경 (4-3).*

| 수치 | 이름 | 기본값 | 범위 (간격) |
|---|---|---|---|
| θ1 구간 속도 하한 1·2·3 | `laneBand1Kmh` ~ `laneBand3Kmh` | 30, 60, 90 km/h | 30~185 km/h (5) |
| θ1 각도 1·2·3 | `laneTheta1Band1Deg` ~ `laneTheta1Band3Deg` | 25°, 15°, 10° | 5.5~69° (0.5) |
| 조향비 | `steeringRatio` | 1.0 | 1.0~32.75 (0.25) |
| 조향각 부호 반전 | `steeringInverted` | 끔(0) | 0·1 |
| 깜빡이 최소 유지 | `signalMinOnSec` | 1.0초 | 0.1~1.6초 (0.1초) |

- 구간 1이 가장 낮은 속도다. 구간은 3개로 고정하고, 개수를 바꾸려면 스토어 업데이트가 필요하다.
- 속도 하한이 30 km/h부터인 이유: 차선변경 판정은 8.3 m/s(약 30 km/h) 이상에서만 해서, 그보다 낮은 구간은 효과가 없다.
- θ1이 5.5°부터인 이유: θ1이 θ0(5°) 이하이면 이탈 직후 바로 복귀로 판정돼 차선변경 검출이 무너진다.
- θ1과 θ0은 핸들 각 기준으로 둔다. 엔진은 이 값을 조향비로 나눈 뒤 입력 조향각과 비교한다. 조향비 1.0은 에뮬레이터용이고, 실차는 13~16으로 추정한다 `[확인필요]`.
- 조향각 부호 반전은 깜빡이 방향 매칭(4-3b)에만 쓴다. 실차 부호가 반대로 오면(9-2) 켠다.
- 깜빡이 최소 유지 시간은 실차가 깜빡이를 점멸 단위로 보내면 ON 구간이 1초보다 짧아질 수 있어 열어 둔다 `[확인필요]`.

*세션 (3-1).*

| 수치 | 이름 | 기본값 | 범위 (간격) |
|---|---|---|---|
| 정차 종료 시간 | `sessionEndIdleSec` | 180초 | 120~2010초 (30초) |

- 2분부터인 이유: 그보다 짧으면 신호 대기마다 세션이 끊겨 1km·3분 미달 세션이 생긴다.
- 시연 빌드의 10초는 원격 값이 아니라 앱 설정으로 넣는다.

**함께 보내는 수치**

아래 묶음은 관계 규칙이 있어 함께 보낸다. 묶음 일부만 오면 거절한다.

- 임계값 A1, A2, B1, B2와 급제동 안정 판정 가속도
- 급가속 단위감점 1·2단계
- 급제동 단위감점 1·2단계
- F_same과 F_all
- θ1 구간 속도 하한 3개와 θ1 각도 3개

**관계 규칙**

- A1 ≤ A2, B1 ≤ B2
- 단위감점 1단계 ≤ 2단계 (급가속·급제동)
- F_all ≤ F_same. 넘으면 F_same이 아무 일도 하지 않는다.
- 급제동 안정 판정 가속도 > −B1 (m/s²로 바꾼 값). 아니면 급제동 수준의 감속도 "안정"으로 본다.
- 구간 속도 하한은 구간 1 < 구간 2 < 구간 3
- θ1은 빠른 구간일수록 같거나 작다: 구간 1 ≥ 구간 2 ≥ 구간 3

**열지 않는 수치**

위 표에 없는 수치는 모두 원격으로 바꾸지 않는다. 신호 처리 구조나 판정 방식에 묶여 있기 때문이다. 대표적인 것은 다음과 같다.

- 재표본화 간격(100ms), 평활 샘플 수, 링 버퍼 길이, 가속도 창(1초). 엔진은 이 값이 다른 설정을 받지 않는다.
- 지속 시간(0.3초), 쿨다운(3초), stale 판정, 후진 직후 제외 시간
- θ0, 차선변경 판정 속도(8.3 m/s), 차선변경 시간값(기준선·커브·2단계·복귀·쿨다운·깜빡이 창)
- 세션 시작·정차 속도, 기어를 모를 때의 시작 대기(5초)
- 심각도 처리 방식(4-0-1 a/b/c), 정규화 거리(10km)
- 최소 유효 세션(1km·3분). 미션·경험치 지급 기준이라 바꾸면 사용자 간 공정성이 흔들린다.

**전송 형식**

JSON으로 보낸다. 위 수치를 모두 넣어도 약 1KB다.

비트필드 압축은 쓰지 않는다. HTTPS 요청 한 번의 연결과 헤더만 수 KB라 줄어드는 양이 작고, 운영자가 값을 직접 읽고 고칠 수 없게 된다. 필요해지면 앱 버전을 올려 추가한다. 이때를 위해 상한을 뺀 수치의 칸 수(k의 최댓값 + 1)를 2의 거듭제곱으로 잡아 두었다.

## 7. 검증과 시연

검증(엔진이 맞게 동작하는가)과 시연(심사위원에게 보여주는 영상)은 **다른 도구로 따로** 한다. Virtual Console은 손으로 카드를 누르는 방식이라 "같은 1초 구간 안에 감속과 페달"처럼 타이밍이 중요한 조건을 재현할 수 없다. 검증은 JSON 시나리오 단독, Virtual Console은 영상용이다.

### 7-1. 검증 시나리오 (JUnit, FakeScenarioSource 단독)

모든 시나리오는 gear = D, 세션 거리 10km(정규화 계수 1)로 가정. 조향각은 θbase = 0 기준. 속도·페달·조향·깜빡이·기어·틱이 **전부 JSON 안에** 들어 있고, 에뮬레이터는 쓰지 않는다. "2단계" 표기와 점수 계산은 심각도 후보 (b)를 가정한 것이다(4-0-1).

JSON 시나리오 형식(가안):

아래는 `scenarios/S03_harsh_brake.json`의 형식 발췌다. `...`로 줄인 구간은 실제 파일에서 100ms 또는 1초 간격으로 이어진다. 전체 형식은 `scenarios/README.md`를 따른다.

```text
{
  "name": "S3_harsh_brake",
  "signals": [
    { "t": 0,      "gear": "D" },
    { "t": 0,      "speed": 0 },
    { "t": 0,      "brake": false },
    ...                                  // 3.1~18초: 0 → 60 km/h 완만한 가속
    { "t": 18000,  "speed": 16.67 },
    ...                                  // 18~23초: 정속, 1초마다 speed
    { "t": 23000,  "brake": true },
    { "t": 23000,  "speed": 16.67 },
    ...                                  // 23~25초: 60 → 10 km/h 급제동
    { "t": 25000,  "speed": 2.78 },
    { "t": 26000,  "brake": false },
    ...                                  // 28~48초: 10 → 60 km/h 완만한 가속
    { "t": 48000,  "speed": 16.67 },
    ...                                  // 48~248초: 정속 200초, 1초마다 speed
    { "t": 248000, "brake": true },
    ...                                  // 248~268초: 완만한 감속
    { "t": 268000, "speed": 0 },
    { "t": 268500, "brake": false }
  ],
  "tickEveryMs": 1000,
  "endAt": 478000,
  "distanceKmOverride": 10,
  "expect": {
    "valid": true,
    "events": [ { "type": "HARSH_BRAKE", "severity": 2 } ],
    "scoreByMode": { "b": 93, "a": 95, "c": 95 }
  }
}
```

- `t`는 시나리오 시작 기준 ms. `FakeScenarioSource`는 `t` 순서로 신호를 흘리고, `tickEveryMs`마다 `onTick(t)`을 부른다. 마지막 신호 뒤 `endAt`까지 틱만 흘려 정차 3분 자동 종료를 일으킨다.
- 유효 세션(1km·3분)을 채우려면 시나리오에 **정속 주행 구간(예: 200초)**이 들어가야 한다. 위 예시의 48~248초 구간이 그것이다. 달리는 구간에는 speed 신호를 최소 1초마다 넣어 stale(2-2)에 걸리지 않게 한다.
- `distanceKmOverride`가 있으면 러너가 첫 신호 시각에 `TripDistance(0 m)`, 마지막 신호 시각에 `TripDistance(값 × 1000 m)`를 주입한다. 짧은 신호열로 긴 세션의 거리를 흉내 내기 위한 값이다. 인정 시점을 검증하는 시나리오(S15)는 이 값을 쓰지 않는다.
- JUnit 테스트 하나가 폴더의 JSON 전부를 읽어 `expect`와 비교한다. 시나리오 추가 = JSON 파일 추가.
- 같은 `t`에 신호가 둘 이상이면(예: speed와 gear) **파일에 적힌 순서대로** 흘린다.
- S5~S9(차선변경)는 에뮬레이터용 θ1(4-3)으로 작성한다. 조향각 부호(9-2)가 확인되는 대로 JSON을 만든다. S11·S15의 조향값도 같은 기준이며 부호 확인 결과에 따라 뒤집을 수 있다.
- 임계값 A1, B1이 미정이므로 JUnit은 **두 후보 설정(공단 / 블루링크)으로 각각** 돌린다(파라미터화 테스트). S1~S16은 어느 후보에서도 같은 결과가 나오도록 속도값을 잡았다. 결정 뒤에는 채택한 설정 하나만 남겨도 된다.

### 7-2. 시연 영상 (에뮬레이터 + Virtual Console)

가산점용 영상이다. 정확한 타이밍이 아니라 "차량 신호가 들어오면 앱이 반응한다"를 보여주는 게 목적이라 세 장면이면 된다. 속도 주입 가부(1-1절 분기)에 따라 속도만 JSON 또는 adb로 넣는다.

| 장면 | Virtual Console 조작 | 화면에 보일 것 |
|---|---|---|
| V1 급제동 | 속도 60 km/h 주입 상태에서 Brake Pedal 카드를 0 → 80%로, 속도를 20 km/h로 | 이벤트 로그에 HARSH_BRAKE 2단계, 제동 점수 하락. 약 2초 뒤 캐릭터 음성 "앗, 깜짝이야!" (영상에 소리 포함) |
| V2 깜빡이 없는 차선변경 | 속도 80 km/h, Turn Signal OFF인 채 Steering Angle 슬라이더를 0 → -20 → +20 → 0 (5초 안에) | LANE_CHANGE_NO_SIGNAL, 매너 점수 하락 |
| V3 깜빡이 켠 차선변경 | 같은 조작을 Turn Signal LEFT를 먼저 켜고 | LANE_CHANGE_SIGNALED, 감점 없음 |

조향각 카드가 슬라이더인지 숫자 입력인지 미확인(9절). 숫자 입력이면 V2·V3의 "5초 안에"가 빠듯할 수 있어, 영상용 빌드에서는 `EngineConfig`의 제한 시간을 늘린 설정을 써도 된다. 그 경우 영상 자막에 "시연용 완화 설정"이라고 적는다.

### 9-2. 미확인 사항

**확인됨 (2026-11-03, 에뮬레이터 실측 + AAOS 공식 문서)**
- 속도: 연속 콜백(10~20Hz), 후진 시 음수. 주입은 Virtual Console HTTP API로 가능, `adb inject`는 불가.
- 조향각: 에뮬레이터는 Virtual Console 카드 값을 그대로 준다(90° → 90). AAOS 공식 정의는 앞바퀴 각이라 실차는 다르게 올 수 있다(2절, 4-3).
- TTS: 에뮬레이터에 시스템 TTS 엔진 없음. 녹음 클립만.
- 조향각 카드는 Virtual Console에서 숫자로 넣을 수 있다(HTTP API 포함).

**미확인**
- 조향각 **부호**: Virtual Console에 +90°를 넣으면 `PERF_STEERING_ANGLE`에 -90으로 왔다. 카드의 +가 왼쪽인지 오른쪽인지 확인해야 한다. AAOS 정의는 왼쪽 음수. 이게 틀리면 깜빡이 방향 매칭(4-3b)이 반대로 된다. 반대로 오면 원격 수치 `steeringInverted`로 바로잡는다(6-1).
- Vehicle SDK `getCurrentSteeringWheelAngle`이 표준 `PERF_STEERING_ANGLE`과 같은 값인지. 다르면 어느 쪽을 쓸지 정해야 한다.
- 실차에서 조향각이 실제로 앞바퀴 각으로 오는지, 그때 차선변경 시 크기가 얼마인지 (θ1 실차값 보정용). **보정 데이터 확보 방법 미정** — 팀원 실차 주행 로그 수집 가능 여부 확인 필요
- Pleos 에뮬레이터에서 dangerous 권한(`CAR_SPEED`, `READ_CAR_STEERING_STATE_3P`) 런타임 요청 다이얼로그가 실제로 뜨고 허용되는지
- `IGNITION_STATE`(0x11400409)를 서드파티 앱이 `CarPropertyManager`로 읽을 수 있는지. 되면 세션 종료에 시동 OFF를 쓴다(3-1)
- 트립 거리(`DistanceDrivenListener`) 단위가 m인지 km인지
- 비상등을 켰을 때 TurnSignal 콜백에 무엇이 오는지 (SDK enum에 비상등 값 없음)
- 내비 안내 음성과 겹칠 때 오디오 포커스가 실제로 거부되는지, 아니면 동시에 나오는지

- 한국교통안전공단 위험운전행동 11개 기준 (운행기록분석시스템 eTAS): 급가속 11 km/h/s 이상, 급감속 7.5 km/h/s 이상, 급진로변경 30 km/h 이상에서 가감속과 방위각 변화 동반 (기억에 의존, 원문 대조 전). 공단 기준은 **방위각(차량 진행 방향)**을 쓰고 우리는 **조향각(핸들)**을 쓰므로 각도 수치는 그대로 옮길 수 없다.
- 텔레매틱스 업계 관행: 급가속·급제동 0.3~0.4g (추정, 출처 미확인).
- 승차감 지표로 저크(가속도 변화율, m/s³)가 있으나 MVP에서는 제외.
